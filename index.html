Hypothesis Ledger

An agent that generated trading strategies, pre-registered them before measuring, put them through nine statistical critics, and held back a slice of data it could touch once in each hypothesis's lifetime. After 11,514 hypotheses and 50,794 measured configurations its answer was zero survivors — and the system's value is that this zero can be trusted. The search is closed; this page is its record, and the bench below runs on the same engine and the same data.

01

The loop

The agent ran itself once a day. What separated it from an optimiser was not how it searched but what it was forbidden to do: it could not move the bar, it could not rewrite a hypothesis, and it could not look at the sealed data again.

INVARIANT 1

Pre-register before measuring

The hypothesis enters libro.db with its canonical genome hashed and its prediction written down. It is never rewritten. Two authors proposing the same thing are the same hypothesis and do not count twice toward multiplicity.

INVARIANT 2

Learn where to search, never where to put the bar

The agent kept a Beta posterior per family and per author to decide where to spend the next attempt. The threshold was set by Romano-Wolf using the whole project's N, and that code the agent could not touch.

INVARIANT 3

If something breaks the above, it is a bug

Day one produced 300 hypotheses, Reality Check p = 0.68 and zero survivors. That is the proof the vetoes work. An agent that finds something on its first day has a broken bar.

05

Frequency does not destroy the edge: it makes self-deception harder

Across 4,908 hypotheses, the expectancy of a strategy drawn at random is ≈ −0.13 R at any frequency — the correlation between frequency and expectancy is ρ = −0.018, p = 0.21. What changes with frequency is the dispersion, and with it how easy it is to mistake noise for a finding.

07

The bug ledger

A system that only publishes its hits is not auditable. These four defects are real, they were found auditing the agent itself, and every one of them would have produced a false finding.

Cache · 960 of 5,008 rows corrupted

A dictionary keyed on id() returns the previous object's data

CPython reuses freed memory addresses, so the indicator cache served USDCHF's ATR when XAUUSD's was requested, producing R = −170. My own 190× optimisation exposed it: once it stopped churning memory, addresses started being reused. The key became a fingerprint of the series, not its address.

Accounting · +0.15 bp per trade

Charging a round turn per bar when the signal persists

The backtest re-evaluated the signal every 30 minutes and charged entry and exit each time. But the signal persists 1.3–1.9 consecutive slots of the same sign: the position is continuous and only one round turn is paid. Cost is charged per change of position, not per bar evaluated.

Statistics · 129× turned into 1.05×

A binomial that assumes fourteen independent tests

The cross-sectional replication criterion compared "wins in 8 of 14" against a binomial of fourteen independent trials. At ρ = 0.42 the effective instruments are 2.2. The warning had been written in my own notebook eight days earlier; the failure was not ignorance, it was not re-reading my own work.

Test design · the seal was never measured

Filtering the sealed set by a date the partition already excluded

The partition function returns (in-sample, search, seal) and the audit used the middle slice, which excludes the seal by construction. Filtering it by "date ≥ seal" necessarily returned empty — and an empty seal looks like a passed test if nobody checks the count.

The directional conditions vote buy or sell and must all agree; one that has no opinion on that bar blocks the entry rather than voting yes by omission. Filters give no direction: they only let the trade through or not.
